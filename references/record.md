# 프로젝트별 최소 기록

기록은 작업을 재개하고 선택·이해의 근거를 구별하기 위한 것이다. 기록량·파일 수를
성장 지표로 삼지 않고, 파일을 만들었다는 사실만으로 실제 작업이나 학습이 일어났다고 하지 않는다.

## 위치와 갱신

현재 대화에서 확정한 프로젝트와 기존 기록 관례를 먼저 확인한다. 적합한 작업 기록이
있으면 그곳의 관련 절을 재사용한다. 과제나 저장소의 공식 산출물과 충돌하는 별도
지침·기록을 강제하지 않는다.

기존 기록이 없고 프로젝트가 확인되면 프로젝트 안의 `WORK_LEARNING.md` 하나에
필요한 항목만 남긴다. 같은 파일이 있으면 먼저 읽고 사용자가 작성한 본문과 다른
작업의 기록을 보존한다. 현재 디렉터리가 다운로드한 예제·참고 저장소·스킬 패키지라면
그곳을 프로젝트로 오인하지 않는다.

프로젝트가 불분명하면 임의의 디스크 위치를 골라 쓰지 않는다. 대화 안에서 최소 상태를
유지하며 지속 저장이 실제로 필요할 때 위치를 확인한다. 쓰기가 불가하면 미저장을
알리고 복사할 수 있는 최소 인계 맥락을 제공한다. 스킬 원본 폴더에 사용자의 작업
자료·답변·진도를 저장하지 않는다.

다음에 영향을 주는 변화가 있을 때 기록을 갱신한다.

- 목표·성공 조건·범위·지도 또는 중요한 가정의 변경.
- 중요한 선택·위임과 그 근거, 실제 검증의 결과.
- 사용자의 새로운 수행 근거, 어긋남·보완, 미응답·연기.
- 작업 중단·재개·마무리의 상태와 다음 복귀점.

매 명령·모든 답변을 전문 복제하지 않는다. 위치·원자료·실행 결과가 이미 있으면
필요한 참조와 한정된 해석을 남긴다. 개인 공통 학습 원장이나 추가 파일들을 자동 생성하지 않는다.

## 보존할 내용

아래는 기록에서 빠뜨리지 않을 의미이지 필수 출력 템플릿·고정 스키마가 아니다.
현재 필요한 절만 사용한다.

**현재 작업과 지도**

목표·사용 장면·성공 조건·입력→처리→결과의 관계, 확인된 사실·가정·열린 질문,
이번 학습 초점과 맡긴 범위. 현재 판본이나 적용 조건이 중요하면 함께 남긴다.

**중요한 결정**

무엇을 결정했는지, 제안자·선택자·위임 범위, 대안과 기준, 당시 알았던 근거·
미확인, 영향받는 부분. 기록에 없는 심리나 비교 과정을 만들어내지 않는다.

설계·예측 경로에서는 사용자가 연결한 원리·잠정안과 AI가 제안한 내용을 구분하고, 중요한
실행 **전** 예상·이유·판단 기준·생각을 바꿀 조건을 같은 기록에 덧붙인다. 이미 실행했다면
사전 예상 없음으로 두고 사후 해석을 적는다. 결과를 본 뒤 예측·기준을 맞춰 쓰지 않는다.

**산출물 검증**

대상·조건·방법·실제 관찰·위치와 적용 범위. 계획, 실행 시도, 실행 성공, 요구 충족,
해석 타당성을 구별한다. 검사한 항목이 없거나 확인 불가면 그 상태를 남긴다.

실제 결과와 사전 예상의 차이, 그 차이로 유지·수정·보류한 선택과 근거를 연결한다.
검사 설계·구현·가정 중 무엇을 확인했고 무엇이 미확인인지 남긴다. 새 기준을 정했다면
변경 이유·적용 시점을 구분한다. 생각이 바뀌었다는 진술을 실제로 수행한 수정으로 바꾸지 않는다.

**사용자 이해와 수행**

다룬 주제, 설명·시범 제공 범위, 자기평가, 실제 제시한 새 사례와 응답/행동,
지원 조건, 근거에 비춘 한정된 관찰, 보완·미확인. 수행하지 않은 질문에 가상 응답을
채우지 않는다. "이해했어"는 이동 의사이자 자기평가로 보존한다.

공백 진단에서는 해설 전 실제 응답, 어떤 주장과 근거가 어긋났는지, 보완한 연결,
다른 사례의 재확인 결과·지원 범위 또는 대기를 구별한다. 해설 후 응답으로 사전 이해를
소급하지 않으며 질문·해설을 생성했다는 사실만으로 공백을 해소했다고 기록하지 않는다.

**다음 복귀점**

대기 중인 업무 결정과 이해 확인을 구분하고, 계속 가능한 일·멈춘 의존 작업·다음
확인할 자료·학습을 연결한다. 관련 기능이나 개념이 다시 등장할 때 배움을 재사용한다.
복습할 기회를 적는 것만으로 일정·자동 알림을 생성하지 않는다.

## 주체와 시점의 구분 예시

| 실제 일어난 일 | 기록 |
|---|---|
| AI가 방법 A를 추천함 | AI 제안. 사용자의 채택·이해는 아직 미확인 |
| 사용자가 기준 B로 A를 선택하고 이유를 말함 | 사용자 선택과 실제 말한 기준. 기술 숙달은 별도 |
| 사용자가 "여긴 우선 네가 정해줘"라고 함 | 명시적 위임의 범위와 AI의 선택. 사용자 숙달로 승격하지 않음 |
| 답변 없이 다른 작업으로 넘어감 | 미응답/대기. 동의나 위임을 추정하지 않음 |
| 완료 뒤 코드를 보고 합리적인 이유를 찾음 | 사후 해석과 현재 근거. 당시 사용자 판단으로 소급하지 않음 |
| 사용자가 설명과 같은 답을 반복함 | 설명 재현. 새 조건 적용은 미확인 |
| 도움을 받아 변형 사례를 해결함 | 실제 수행과 도움의 종류. 무지원 수행과 구분 |

## 정정·재개·변경의 처리

가정이 확인되거나 반박되면 현재 상태를 갱신하고, 중요한 이전 전제와 바뀐 근거를
짧게 보존한다. 사용자의 정정을 AI 추정으로 덮지 않는다. 예전 선택이 잘못되었다고
당시 의도를 새 이유로 다시 쓰지 않는다.

재개할 때 기록과 최신 자료·산출물·요청을 대조한다. 과거 기록은 문맥이지 현재
사용자의 의사나 권한을 대체하지 않는다. 이미 해결된 질문을 다시 묻지 않고,
변경으로 무효가 된 검증·이해 근거만 한정해 재확인한다.

대기 중인 새 사례가 있으면 그 질문과 응답 상태를 복구한다. 사용자가 계속 확인을
원하는지 현재 요청으로 판단하며, 답을 기다리는 상황에서 먼저 정답을 노출하지 않는다.
설명으로 바꾸거나 생략해 달라는 요청은 존중하고 상태를 갱신한다.

미확인은 결함이나 실패와 다르다. 산출물이 충분히 확인되었지만 사용자 이해는
미확인일 수 있고, 사용자가 원리를 설명해도 현재 산출물은 잘못되어 있을 수 있다.
마무리에서 이 둘을 분리하고 필요한 다음 행동을 알려준다.
