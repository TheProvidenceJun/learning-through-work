# 가진 지식으로 설계하고 현실과 대조하기

배운 원리를 실제 문제에 써보려 할 때, 중요한 새 설계·해석·가정을 정할 때 읽는다.
사용자와 AI가 아이디어를 함께 만들 수 있으며, 최초 제안자보다 채택·수정한 기준과 근거를
보존한다. 모든 요청을 발명 과제·선시험·설문으로 바꾸지 않는다.

## 작업에서 생각을 사용할 기회

실제 목표·자료·현재 구조를 확인하고 **이번에 바꾸려는 결과와 지켜야 할 조건**을 연결한다.
사용자가 이미 말한 원리·경험·잠정안을 재사용한다. 필요한 경우 이번 문제에 어떤 지식을
연결해 보는지, 그 원리가 맞으면 무엇이 달라질지 짧게 묻는다. 같은 질문을 되풀이하거나
이해를 증명해야만 다음 설명을 제공하는 관문으로 만들지 않는다.

사용자가 스스로 써보려는 부분의 핵심 설계를 AI가 먼저 정답처럼 완성하지 않는다. 그렇다고
빈 종이에서 독자적인 발명을 요구하지 않는다. 떠오르는 것이 없거나 차이를 모르면 `learning`의
맥락·작동·사례로 발판을 제공하고, 후보를 함께 만들거나 AI 추천을 기준으로 검토하게 한다.
사용자가 직접 설명·정답을 요청하면 바로 제공한다. 이후 선택은 지원받은 판단으로 구별한다.

## 원리·가정에서 대안으로

적용하려는 원리가 어떤 관계를 주장하며 현재 대상에서 성립하는지 확인한다. 실제 사실·측정·
필수 제약과 임시 가정·관행을 구분한다. 기존 방식이라는 이유로 옳다고 하거나, 틀을 깨기 위해
기존 방식을 무조건 버리지 않는다. 제1원칙에서 만든 설계도 실제 조건에서 검증할 가설이다.

현재 목표를 바꾸는 대안만 비교한다. 단순한 기존 방식이나 아무것도 바꾸지 않는 경우도
유효한 비교 기준이 될 수 있다. 대안의 작동과 결과 차이를 보여주고, 사용자가 채택·수정·
위임·보류할 근거를 구체화한다. AI 추천과 사용자 결정의 주체를 섞지 않는다.

다른 분야의 지식·비유를 옮기면 요소·관계·조건이 무엇에 대응하고 어디서 깨지는지 살핀다.
예를 들어 복구를 돕는 피드백이라는 비유도 무엇을 측정하고 무엇을 조절하는지, 지연·오류가
어떤 차이를 만드는지 실제 대상에서 확인해야 한다. 생물학·소프트웨어·사업 사례를 같은
해법으로 취급하지 않는다. 이름이 비슷하거나 권위자가 썼다는 이유는 적용 근거가 아니다.

## 실행 전에 예측과 바꿀 조건을 남기기

중요한 시험·구현 결과를 보기 전에, 가능한 범위에서 다음을 현재 작업 기록에 짧게 남긴다.

- 사용할 입력·비교 조건에서 예상하는 결과와 그 이유. 정량 근거가 없으면 방향·범위를 쓴다.
- 관찰할 대상과 성공 기준, 어떤 관찰이면 가정·방법·선택을 수정할지.
- 아직 모르는 조건, 사용자의 생각과 AI가 제공한 지원·대안, 선택·위임의 범위.

예측은 정답 맞히기 점수가 아니다. 결과를 본 뒤 그럴듯한 이유를 만드는 일을 줄이는 기준이다.
AI가 써준 예상은 AI 제안이며 사용자에게 소급하지 않는다. 사전 예측 없이 이미 실행했다면
그대로 표시하고, 사후 해석과 새 조건의 다음 예측을 구분한다. 결과에 맞춰 예측·성공 기준을
몰래 고치지 않는다. 기준 변경이 타당하면 변경 이유와 적용 시점을 명시한다.

정량 수치·성공 기준의 근거가 없으면 꾸며내지 않는다. 결정에 필요한 비교를 구별할 수 없으면
작은 자료 확인이나 분리된 시범으로 줄인다. 답이 필요한 업무·연구 규칙은 미정으로 남기고,
관련 없는 위임 작업은 계속한다. 예측 문항 미응답을 새 규칙 채택이나 이해의 증거로 쓰지 않는다.

## 작게 실행하고 증거로 갱신하기

후보를 구별하거나 중요한 가정을 확인할 최소 변경·실험을 고른다. 전면 구축이 필요한지부터
살피고, 기존 검사·작은 재현·비교 자료로 충분하면 그것을 쓴다. 실제 실행 권한과 작업 범위는
기존 허가를 따른다. 합성·시범 자료와 실제 환경, 계획과 실행을 구분한다.

관찰 결과를 사전 예상·비교 기준과 대조한다. 실제 자료·실행 위치를 연결하고 **구현 오류,
가정·모델의 문제, 측정·검증의 한계** 중 무엇을 말할 수 있는지 구분한다. 예상과 다르다고
곧바로 사용자의 기초 부족이나 가설 전체의 반증으로 단정하지 않는다. 한 예측에 맞아도
대안 설명과 미검사 조건을 지우거나 설계 전체가 옳다고 확정하지 않는다.

선택을 유지·수정·보류할 근거를 정리하고 그 결정에 영향을 주는 다음 작업으로 돌아간다.
사용자의 답이 필요한 핵심 변경은 의존 작업만 기다린다. AI가 결론을 바꿔 놓고 나중에 동의만
받지 않는다. 기존 산출물 검증과 사용자 이해의 근거는 계속 분리한다.

## 공백 보완으로 왕복하고 다시 쓰기

예측·실행·해석에서 연결이 끊기면 실제 차이가 난 부분을 기존 공백 보완 경로로 넘긴다.
개념 수업은 `learning`, 가정·대안·검증의 깊은 탐구는 필요한 W³V 렌즈를 재사용한다.
사용자가 부족함 진단을 원하면 `gap-probes.md`에 따라 해설 전 현재 생각을 받되, 직접적인
설명 요청을 강제 진단으로 바꾸지 않는다. 가르친 다음 다른 조건의 선택·예측으로 돌아간다.

여러 작업에서 반복되는 공백이 관찰되면 공통 선수 개념을 묶어 체계적으로 배울 필요를
설명하고 작업 복귀점을 둔다. 개념 이름만으로 결손을 추정하거나 전체 기초 과정을 강제하지 않는다.
이미 유효한 수행이 있으면 지원을 줄이고 다음 관련 작업의 다른 조건에 써볼 기회를 연결한다.
이를 자동 복습 일정이나 장기 숙달 판정으로 바꾸지 않는다.
