# 실제 결과물에서 공백을 드러내는 후속 질문

사용자가 부족함·착각·자기 판단을 확인해 달라고 하거나, 진행 중 이해했다고 한 중요한
부분을 점검할 때 읽는다. 질문의 날카로움은 압박의 정도가 아니라 **답을 실제 산출물과
대조해 어떤 연결이 빠졌는지 구별할 수 있는가**에 달려 있다.

## 현재 생각을 먼저 확인하기

원래 요구·구현·자료·검사 결과·결정 기록을 확인하고, 목표에 중요한 판단 하나를 고른다.
자료가 없으면 필요한 작은 부분을 요청하고 진단은 보류한다. 없는 코드나 당시 행동을
추측해서 추궁하지 않는다. 산출물에 결함이 있어야만 진단할 수 있는 것은 아니다.

진단 대상의 해설·예상 결함·정답을 먼저 나열하지 않는다. 이해에 필요한 중립적인 상황과
입력·조건은 충분히 제공한다. 실제 산출물의 한 조건을 바꾸거나, 성공한 검사와 다른
상황을 주고 **결과 예측과 그 경로·근거**를 묻는다. 이유만 물어 그럴듯한 사후 설명을
받는 대신, 그 이유가 참이면 새 조건에서 무엇이 달라질지 확인한다. 모든 렌즈를 한꺼번에
묻거나 고정 문항을 암기시키지 않는다.

현재 작업에 맞게 다음 관점 중 필요한 것을 고른다.

| 확인할 연결 | 질문에서 드러나게 할 것 |
|---|---|
| 요구와 가정 | 무엇이 명시된 요구이고 무엇을 가정했는가. 가정이 바뀌면 무엇을 바꿔야 하는가 |
| 선택과 목적 | 어떤 기준으로 이 방법을 채택했는가. 다른 방법이 나아지는 조건은 무엇인가 |
| 작동과 실패 | 주어진 입력이 어떤 단계를 거쳐 결과가 되는가. 조건 변경이 어느 단계에 영향을 주는가 |
| 검사와 주장 | 실제 검사가 무엇을 확인했고, 어떤 주장은 아직 뒷받침하지 못하는가 |
| 판단의 주체 | 당시 직접 정한 기준·맡긴 범위·AI 제안은 무엇이며, 지금 알게 된 이유와 어떻게 다른가 |

예를 들어 "이 기능은 중복을 막지?"보다, 실제 코드와 검사 기록을 두고 "다른 창에서
같은 입력을 보내면 저장 결과를 어디까지 예상할 수 있어? 어느 코드와 검사가 근거야?"가
유용하다. 연구에서는 실제 자료로 결론을 바꿀 수 있는 조건을, 문서에서는 독자나 증거가
바뀌었을 때 유지할 주장·고칠 주장을 묻는다. 특정 동시성 해법이나 통계 용어가 정답인
질문으로 고정하지 않는다.

사용자가 처음 배우는 부분이라고 하거나 힌트·설명·정답을 요청하면 제공한다. 그 뒤
수행은 지원받은 수행으로 남긴다. 실제 위험이나 잘못된 외부 제출을 막아야 해서 먼저
결함을 알려야 하면 바로 알리고, 이미 알려준 부분을 사전 이해의 증거로 평가하지 않는다.

## 응답을 근거와 대조하기

확신, 전문용어, "테스트 통과", "AI가 검증함"만으로 통과시키지 않는다. 답이 모호하면
해당 단계의 입력·출력이나 반례를 구체적으로 추적하게 한다. 답변이 근거와 맞으면 그
범위의 이해를 인정한다. 반드시 결함을 찾으려고 질문을 계속 늘이지 않는다.

틀렸다면 실제 말한 주장과 코드·자료·관찰이 어긋나는 지점을 직접 짚는다. 예를 들어
"동시성을 모른다"는 총평보다 "네 답에서는 한 화면의 상태가 다른 화면도 막는다고
가정했는데, 이 변수는 각 화면에 따로 있어"처럼 빠진 연결을 특정한다. 설명 가능한
실패 경로와 실제 재현된 실패를 구분하고, 실행 환경이 없으면 발생을 확정하지 않는다.

다음을 섞지 않는다.

- 산출물의 오류와 사용자의 이해 부족: 오류만 보고 사용자가 몰랐다고 판정하지 않는다.
- 미학습·미응답·표현 곤란과 잘못 알고 있다는 응답: 관찰된 차이만 진단한다.
- 당시 기록 부재와 의도 부재: 나중의 자기보고는 자기보고로 보존하고 기록과의 관계를 확인한다.
- 현재 설명과 과거 선택: 사후 이유를 당시 의도로 바꾸지 않는다.

## 공백을 보완하고 다시 적용하기

피드백에는 **맞게 연결한 부분, 어긋난 주장과 근거, 필요한 개념·판단 기준**을 현재 답에
맞게 담는다. 고정 성적표나 종합 능력 등급은 만들지 않는다. 배울 부분은 `learning`으로
연결해 왜 필요한지와 중간 논리를 실제 작업에서 설명·시범으로 보충한다.

그 다음 답을 그대로 복창할 수 없는 다른 입력·조건에서 예측·선택·작은 수정으로
재확인한다. 직전 피드백을 반복했어도 새 사례에 적용하지 않았다면 설명 재현까지만
확인한 것이다. 맞은 재확인은 해당 조건과 지원 범위의 근거이며 장기 숙달을 보장하지 않는다.
어긋나면 남은 연결을 좁히거나 사용자의 요청에 따라 다음 관련 작업으로 넘긴다.

기록에는 최초 응답과 지원 시점, 관찰된 어긋남, 배운 내용, 재확인 결과 또는 대기를
필요한 만큼 남긴다. 질문을 만들거나 해설을 제공한 것만으로 공백을 해소했다고 쓰지 않는다.
사용자가 미루거나 중단하면 미확인으로 두고 맡긴 독립 작업을 계속한다. 이해 확인의
미응답을 제품·연구의 미정 결정을 임의로 채택할 허가로 사용하지 않는다.
