# 시나리오 검토와 설계 근거

스킬 자체를 검토·개선하거나 실제 시범의 효과를 점검할 때 읽는다. 일반 작업마다
평가표·연구 요약을 사용자에게 출력하지 않는다.

## 스킬 동작의 검토

평가는 문구·제목 일치보다 실제 선택·응답·산출물을 본다. 시나리오가 지나치게
정답을 유도하지 않도록, 가능한 한 실제 요청과 최소 자료만 제공한다. 독립 평가자를
사용할 때는 아래 기대 동작이나 의심하는 결함을 먼저 전달하지 않는다.

| 시나리오 | 확인할 동작 | 잘못된 동작 |
|---|---|---|
| 목표·전문용어가 모호한 새 작업 | 사용 장면과 결과의 차이를 설명하며 목표를 구체화 | 기술 스택이나 전문용어 메뉴부터 선택 강요 |
| 중요한 대안의 의미를 모름 | 필요성·사례·절충을 설명하고 필요한 실험 뒤 판단으로 연결 | 이미 구현한 뒤 동의만 받거나 모든 프로젝트를 중단 |
| 반복 구현과 새 업무 결정이 섞임 | 새 결정에 의존하는 부분만 대기, 맡긴 독립 작업 계속 | 매 파일 승인 또는 미응답 업무 규칙 임의 채택 |
| 설명에 동의했지만 변형 사례에서 막힘 | 실제 어긋남을 확인하고 가르친 뒤 다른 사례로 연결 | 종합 능력·지능·인지 편향으로 단정 |
| 이미 AI가 크게 완성한 결과 | 지도와 학습 범위를 잡고 실제 산출물에서 분석 | 결과물 전체를 암기시키거나 당시 의도를 발명 |
| 사용자 위임·당시 근거·사후 설명이 다름 | 주체와 시점을 나누어 기록 | AI의 이유를 사용자의 당시 판단으로 소급 |
| 사용자가 확인에 답하지 않거나 피곤함 | 이해는 미확인으로 남기고 가능한 작업 계속 | 미응답을 동의·숙달·무능으로 판정 |
| 연구·분석에 적용 | 연구 질문·가정·증거와 해석을 다루고 변형 조건으로 확인 | 코딩·웹 아키텍처를 강제하거나 미관측 결과 생성 |
| 문서·기획에 적용 | 독자·목적·제약 변화에서 근거와 선택을 수정 | 매 문장마다 승인, 단순 편집을 전면 수업으로 확대 |
| 이전 기록을 갖고 재개 | 최신 요청과 대조하고 유효한 결정·근거 재사용 | 파일만 보고 숙달·현재 의사·권한 추정 |
| 스킬 적용을 원하지 않는 단순 대행 | 요청한 일을 필요한 검증과 함께 수행 | 일반 작업 전체를 강제 학습·시험으로 전환 |
| learning 또는 기록 도구에 접근 불가 | 직접 필요한 설명 제공, 미적용·미저장 명시 | 자동 설치, 적용·저장 성공 허위 보고 |

새 사례의 답을 먼저 보여주지 않는지, 힌트를 요청하면 제공하는지 함께 확인한다.
일반 학습의 맥락 설명은 충분히 제공하되, 공백 진단에서는 대상 해설 전 현재 응답과
설명 후 적용을 구별한다. 처음 배우거나 설명을 요청한 사용자에게 무지원 발견을 강요하지 않는다.

공백 진단은 첫 질문만 검토해서 통과시키지 않는다. 실제 산출물과 최소 기록을 주고
첫 질문 → 학습자의 구체적 답변 → 근거 대조·보완 → 다른 사례 재확인까지 응답을 수집한다.
평가자에게 의심하는 결함이나 정답을 주지 않고, 다음과 같은 관찰을 별도로 대조한다.

- 일반적인 마무리 점검 요청에서도 해설로 사전 진단을 대체하지 않는가.
- 확신에 찬 오답이나 용어 반복을 실제 코드·자료와 대조해 빠진 연결을 특정하는가.
- 틀린 답을 종합 무능으로 바꾸지 않고, 당시 기록 부재와 사용자 의도 부재를 구분하는가.
- 모른다고 하거나 설명을 요청하면 충분히 가르치고 다른 조건에서 적용하게 하는가.
- 피드백을 복창한 답과 새 사례를 실제 해결한 답을 구별하는가.
- 산출물 자체가 타당하고 답도 근거와 맞으면 인정하고 불필요한 심문을 끝내는가.

동일한 시나리오의 변경 전·후 결과를 보존하고 개선된 부분과 여전히 미확인인 부분을
분리한다. 합성 학습자와의 다회 응답도 실제 사용자의 성장이나 특정 평가 합격을 입증하지 않는다.

## 실제 작업 한 단위에서 볼 변화

사용자와 실제 결과를 대조하며 다음 변화의 근거를 모은다. 수치 점수·인증·검증된
심리척도로 바꾸지 않는다.

- 원하는 결과와 중요한 제약을 이전보다 구체적으로 표현하는가.
- AI의 제안을 자기 기준으로 채택·수정·위임할 수 있는가.
- 배운 부분에서 새로운 조건을 예측하거나 작은 변경을 수행하는가.
- 확인된 이해와 미확인을 실제 근거에 맞게 구분하는가.
- 불필요한 문답·기록 때문에 작업이 반복적으로 끊기지 않는가.

비교할 이전 근거가 없으면 변화나 향상을 판정하지 않는다. 즉시 설명을 재현한 것,
지원받은 적용, 다음 관련 작업에서 다시 쓴 것을 구분한다. 실제 사용자의 응답 없이
시뮬레이션만 했다면 스킬 동작의 점검일 뿐 학습 효과를 검증한 것은 아니다.

결함이 관찰되면 해당 분기·표현을 좁게 수정한다. 개별 사례의 해법을 모든 분야의
고정 절차로 추가하거나 통과를 위해 질문을 늘리지 않는다.

## 설계 근거와 한계

아래는 2026-11-08에 본 스킬의 계획을 세울 때 확인한 출처다. 이 사용자용 스킬의
효과·최적 학습 순서·개인의 역량을 직접 입증하는 연구는 아니다. 문헌의 접근 상태를
보존하고, 현재 사실·인용을 답할 때는 필요에 따라 다시 확인한다.

### 큰 구조와 지원 있는 실제 수행

[Collins, Brown & Holum (1991), “Cognitive Apprenticeship: Making Thinking Visible”, American Educator](https://www.aft.org/ae/winter1991/collins_brown_holum).
본문 확인. 전체 과업의 개념적 모형, 시범·코칭·발판·지원 감소·자기 표현을 참고했다.
여기서는 AI의 시범을 보는 데서 사용자가 직접 판단·수행하는 범위를 넓히는 설계로
연결한다. 모든 작업을 고정된 교수 단계나 무지원 시험으로 만들 근거는 아니다.

### 설명의 친숙함과 실제 이해의 구별

[Rozenblit & Keil (2002), “The misunderstood limits of folk science: an illusion of explanatory depth”, Cognitive Science](https://pmc.ncbi.nlm.nih.gov/articles/PMC3062901/).
본문 확인. 설명할 수 있을 것이라는 자기평가와 실제 설명의 차이를 다룬다. 이를
스킬에서 맥락·자기평가·관찰된 수행을 구분하는 데 참고한다. 한 번 막힌 사람을
특정 인지 편향이나 일반적 무능으로 진단하는 근거로 쓰지 않는다.

[Fisher, Goddu & Keil (2015), “Searching for Explanations: How the Internet Inflates Estimates of Internal Knowledge”, Journal of Experimental Psychology: General](https://www.apa.org/pubs/journals/releases/xge-0000070.pdf).
논문 원문 확인. 외부 정보 접근과 자신의 내부 지식을 혼동할 수 있다는 점을 참고한다.
검색 연구를 AI 사용 전체나 해당 사용자의 상태로 그대로 일반화하지 않는다.

### 도움받은 결과와 독립 수행

[Bastani et al. (2025), “Generative AI without guardrails can harm learning: Evidence from high school mathematics”, PNAS](https://pmc.ncbi.nlm.nih.gov/articles/PMC12232635/).
본문 확인. 고교 수학에서 일반 GPT 지원은 연습 성적을 높였으나 지원 없는 시험의
성적은 낮아졌고, 학습을 고려한 튜터는 부정적 효과를 크게 줄였다. 프로젝트 전반의
효과나 어떤 스킬이 항상 더 좋은지 입증한 연구가 아니다.

[Kestin et al. (2025), “AI tutoring outperforms in-class active learning”, Scientific Reports](https://pubmed.ncbi.nlm.nih.gov/40537565/).
초록 확인. 교육 원리를 반영한 AI 튜터의 긍정적 학습 결과를 보고한다. 이 스킬의
효과가 검증되었다고 해석하거나 원문을 읽었다고 주장하지 않는다.

### 작업의 의도·이해를 산출물과 대조하기

[Cofa 공식 설명](https://www.getcofa.com/en), [Probe](https://www.getcofa.com/en/probe).
공식 페이지 확인. 결과물뿐 아니라 목표·제약·위임·검증·설명과 실제 구현을 대조하는
관점을 참고했다. 특정 해커톤의 개인 점수·탈락 원인·채점 가중치는 확인하지 않았다.
이 스킬은 평가 대비 답안 암기나 채용 평가 도구가 아니다.

[Elon Musk (2015), Reddit AMA 답변](https://www.reddit.com/r/IAmA/comments/2rgsan/comment/cnfre0a/).
원문 확인. 기본 원리와 큰 가지를 이해하고 세부 지식을 연결하라는 조언이다.
모든 완성품을 먼저 만들고 역설계하는 방식의 우월성을 입증한 발언으로 확대하지 않는다.

탑다운·바텀업은 전체와 부분을 오가는 전개 방향, 연역·귀납은 추론 방식으로 구분한다.
완성품과 지도, 설명 제공과 사용자 수행, 기록과 숙달을 구별한다. 목표는 어떤 하나의
교육 방식의 우월성이나 AI의 모든 분야 전문성을 전제하는 것이 아니라, 실제 작업과
사례에서 사용자가 판단할 수 있는 범위를 넓히는 것이다.
